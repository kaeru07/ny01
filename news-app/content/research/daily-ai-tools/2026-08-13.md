## 記事本文

2026年8月13日の調査では、完全に新しい単体AIサービスの増加より、既存のコーディングエージェントがブラウザ、課題管理、レビュー、共有画面まで担当範囲を広げる動きが目立った。GitHubの公式Changelogで7月までに確認できたCopilot browser tools、vision、Linear連携、MCP対応は、AIがコード補完から一連の開発工程を引き受ける実行主体へ移ったことを示している。ただし、8月13日当日公開の公式発表は確認できず、本日の「新規」は直近情報の棚卸しという位置付けである。

特に個人開発への影響が大きいのは、実装と動作確認の距離が縮まった点だ。画像からUIを読み取り、コードを変更し、ブラウザ上で結果を確認する流れを一つのエージェントに寄せられれば、画面数の少ない学習アプリ、診断ツール、広告型ミニサービスを短期間で検証できる。Linear連携も便利だが、一人開発では課題管理サービスを増やすこと自体が負担になり得るため、GitHub IssuesやローカルMarkdownで代替できないかを先に判断したい。

収益化の観点では、AI機能そのものを売るより、エージェントによって検証本数を増やす方が再現性を持ちやすい。例えば、同じ基盤から将棋の局面学習、麻雀の点数練習、資格試験の反復学習といった縦特化サービスを展開し、無料版を広告、有料版を履歴保存や解説強化で差別化する方法が考えられる。一方、GitHub Copilotは2026年6月からAI Creditsを軸とした従量課金を導入しており、長時間エージェントを無制限に回す前提では原価が読みづらい。実行時間、生成PR数、公開まで到達した割合を記録し、サービス一件当たりの開発原価を把握する必要がある。

Codex Sitesは、社内情報を使った対話型サイトを短時間で構成できる方向性を示すが、確認できた提供範囲はBusiness・Enterprise向けプレビューであり、個人開発者が一般公開サービスとして利用できるかは未確認である。それでも、静的な調査報告を操作可能な比較表や収益シミュレーターへ変換する発想は有効だ。Codexの長時間タスク利用が増えているというOpenAIの報告も、成果物単位でエージェントへ委任する流れを補強している。

次に取るべき一歩は、ブラウザ操作を含む小規模な収益化実験を一件だけ作ることである。題材を一問一答型の学習Webアプリに絞り、生成、UI確認、テスト、公開判定までの所要時間とAI Creditsを測定する。その結果から、月額課金を維持できる制作速度か、広告収益で回収できる原価かを判断するのが、本日の情報を実益へつなげる最短経路となる。

## 個人開発で活用できそうなもの

- Copilot browser tools：生成したWebアプリの表示、フォーム操作、主要導線をエージェントに確認させる。短期リリース時の手動テスト削減に向く。
- Copilot vision：競合画面や自作モックのスクリーンショットから、UI改善案と実装タスクを作る。画像の利用権と機密情報には注意が必要。
- GitHub MCP Server：Issue、PR、リポジトリ情報をエージェントへ接続し、調査から修正までを一貫させる。セルフホスト可否は構成により異なり、今回未確認。
- Copilot cloud agent for Linear：不具合票から修正PR作成までを委任する。複数サービスを並行運営する段階で効果が出やすい。
- Codex Sites：調査結果や料金計算を操作可能なデモへ変換できる可能性がある。ただし個人向け提供と外部公開条件は未確認。

## Claude Code/Codex連携可能性

- GitHub MCP Server：MCPクライアントとしてのClaude CodeからリポジトリやIssueを操作する構成が可能。Codex側の具体的接続条件は未確認。
- Linear MCP Server：課題をClaude CodeやCodexの作業単位へ変換し、完了結果をLinearへ戻す。公式サーバーの2026年8月時点の仕様は未確認。
- Playwright MCP：ブラウザ操作と画面検証をClaude CodeまたはCodexへ与え、E2E確認を自動化する。公式最新バージョンは未確認。
- GitHub Copilot SDK：独自アプリからエージェント機能を呼び出し、Codexで周辺実装や評価コードを生成する。利用料金とセルフホスト可否は未確認。
- Google Agent Development Kit：MCP接続を持つエージェントを構築し、Claude CodeやCodexに実装・テストを担当させる。SDKは公開情報あり、実行基盤の費用は構成依存。
