## 記事本文

2026年8月9日の調査では、単体の生成AIアプリよりも、既存の開発工程へエージェントを埋め込む動きが目立った。特にGoogleのGemini API Managed Agentsは、バックグラウンド実行とRemote MCPを同じ実行基盤で扱える。個人開発者にとって重要なのはモデル性能そのものより、調査、生成、外部サービス操作、結果保存を一つのジョブとして完走させられる点である。ただし料金と一般提供範囲が未確認のため、本番採用より小規模な検証が先になる。

開発方法にも変化がある。Conductor Pluginは仕様、計画、進捗を一時的な会話ではなく、バージョン管理可能なMarkdownへ残す。これは複数日にまたがる個人開発で、AIが前日の判断を忘れて設計を崩す問題への実務的な回答だ。GitHub MCP Serverも新しいステートレス仕様へ対応し、セッション管理や初期化処理を減らした。エージェント連携は「専用の複雑な基盤」から、交換可能な小さな部品を組み合わせる方式へ移りつつある。

収益化の観点では、最短距離にあるのは汎用チャットの再販ではない。問い合わせの分類、競合情報の定期収集、ストア説明文の更新案作成、障害やレビュー指摘からの修正案生成など、成果物が明確な小規模自動化である。Managed Agentsを使えば月額制の監視サービスを作りやすく、Conductorを併用すれば顧客ごとの要件と作業履歴を再現可能な形で残せる。一方、従量課金型の高度なモデルを常時使うと粗利が崩れるため、軽量モデルで分類し、難しい案件だけ高性能モデルへ送る設計が必要になる。

GitHub CopilotではClaude Opus 5やGemini 3.6 Flashの選択肢が増え、Linearからクラウドエージェントへ直接作業を渡せるようになった。個人開発でも、Issue作成から修正、テスト、PRまでを非同期化すれば、動画制作や販売活動と開発を並行できる。ただしCopilotは利用量課金の影響を受けるため、すべてを自動委任するのではなく、定型修正、テスト追加、依存更新など完了条件が明確な作業から始めるべきだ。

次の一歩は、新規サービスを大きく作ることではなく、一つの収益候補で短い実証を行うことである。例えば「競合アプリの更新を毎日収集し、改善案をMarkdownで納品する」処理を、Remote MCP、安価なモデル、永続化した仕様書で構成する。1週間分の実行コスト、誤検出率、人間の確認時間を測れば、月額料金を決められる。技術デモではなく、顧客が継続して受け取りたい成果物を基準に評価することが、本日の観測から導ける最も収益化に近い行動である。

## 個人開発で活用できそうなもの

- Gemini API Managed Agents: 競合監視、定期レポート生成、問い合わせ処理をバックグラウンドジョブ化する。料金未確認のため、実測した原価を基に月額商品を設計する。
- Conductor Plugin: 要件、実装計画、検証結果をMarkdownで維持し、Codexや他のCLIエージェントでも再利用できる開発台帳にする。
- GitHub MCP Server: Issue、PR、リポジトリ情報をエージェントへ安全に渡し、定型保守やリリース準備を短縮する。セルフホスト可能なstdio構成がある。
- Copilot cloud agent for Linear: 顧客要望をLinearへ登録し、実装候補を非同期でPR化する。小規模SaaSの保守速度向上に向く。
- Gemini 3.6 Flash: 定型的なコード修正や大量分類へ割り当て、高価なモデルの利用を難しいタスクへ限定する。
