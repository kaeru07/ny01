## 記事本文

2026年8月11日時点で確認できた変化は、単独の生成AIツールが増えたことより、Issue、IDE、リポジトリ、外部データを一つのエージェント作業線へ接続する仕組みが実用段階へ進んだことである。本日公開された新製品は公式情報から確認できず、今回の「新規」は6月末から7月末に公開され、当調査で新たに確認したものを中心とした。したがって、鮮度評価は partial とする。

特に実装へ近いのは、Linear の Issue を Copilot cloud agent に割り当て、モデル、カスタムエージェント、対象ブランチを指定してドラフト PR まで作らせる流れである。個人開発では、要望整理と実装の間にあった手動転記が減り、障害修正や小機能を短い単位で並行処理できる。GitHub Copilot の個人向け価格は Free、Pro 10ドル、Pro+ 39ドル、Max 100ドルであり、小規模な検証は無料枠またはProから始めやすい。一方、エージェント実行はAIクレジットを消費するため、売上前のプロダクトで無制限に走らせる設計は避けたい。

もう一つの重要な変化は、MCPの中核がステートレス化し、GitHub MCP Server が新仕様へ対応したことである。接続時のセッション管理やRedis依存を減らせるため、個人VPSでも複数エージェントへ同じツール群を提供しやすくなる。JetBrains版CopilotでもClaudeエージェントフローからMCPサーバーとカスタムエージェントを利用でき、MCPは実験的な連携規格から、IDEとクラウドエージェントをまたぐ共通基盤へ移りつつある。

収益化では、汎用チャットをもう一つ作るより、「課題受付から修正PRまで」「画像からLP修正まで」「専門データから監査可能なレポートまで」のように、入力と納品物を狭く定義したサービスが有望である。たとえば月額制の小規模サイト保守、依頼票からの定型機能追加、学習アプリ向け教材生成などは、作業時間の短縮を料金差へ転換しやすい。Claude Scienceは専門用途の方向性を示すが、価格と一般利用条件が未確認であり、直ちに採用する候補ではない。

次の一歩は、LinearまたはGitHub Issueを一件だけ起点にし、テスト追加を含む小さなPRをエージェントへ委任して、所要時間、AIクレジット、手戻り回数を記録することである。同時にGitHub MCP Serverは読み取り専用権限から試し、書き込み操作には人間の承認を残す。この一件の原価が把握できれば、月額保守や小機能追加パックの最低販売価格を現実的に設定できる。

## 個人開発で活用できそうなもの

- GitHub Copilot cloud agent for Linear: 不具合や小機能をIssueとして登録し、実装、テスト、ドラフトPR作成まで委任する。月額保守サービスの作業原価削減に向く。
- GitHub MCP Server: CodexやClaude CodeへIssue、PR、リポジトリ情報を安全に渡す。セルフホスト可で、最初は読み取り権限に限定できる。
- Codex Plugins: 調査、設計、実装、記事作成を役割別ワークフローとして再利用する。複数の小規模サービスを同じ手順で量産する用途に適する。
- Copilot vision: スクリーンショットを基にUI修正案や実装を作る。LP改善やアプリ画面の短納期受託と相性がよい。
- Claude Science: 専門データを監査可能な成果物へ変換する方向性は有望。ただし価格と一般提供条件が未確認のため、現時点では市場検証用の参考候補とする。

## Claude Code/Codex連携可能性

- GitHub MCP Server: Claude CodeまたはCodexからIssue取得、コード検索、PR操作を行う。書き込み権限は承認付きにする。
- Codex Plugins: 調査や開発手順と外部ツール接続をパッケージ化し、反復可能な個人開発工程にする。
- GitHub Copilot for JetBrains: MCPとカスタムエージェントをClaudeフローへ接続し、IDE内で専門ツールを呼び出す。
- Linear連携: Linear IssueをCopilot cloud agentへ渡し、CodexまたはClaude Codeで追加レビューする二段階工程を構成できる。
- OpenTelemetry: エージェント実行の時間、失敗、トークン利用を観測し、案件単位の原価測定へつなげる。
