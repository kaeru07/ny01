## 記事本文

2026年8月10日の調査では、当日公開された新製品を公式情報から十分に確認できなかった。その一方、7月後半までに明確になった変化は、AIツールの競争軸が「コードを提案する能力」から「課題管理、実装、検証、レビューを一続きで処理する能力」へ移ったことである。LinearからCopilot cloud agentへ課題を割り当て、作業中に指示を追加し、最後にドラフトPRを受け取れる流れは、その代表例だ。個人開発者にとっては、エディタ内の補完速度より、未処理チケットをどれだけ少ない監督で出荷可能な状態へ移せるかが重要になりつつある。

基盤側では、GitHub MCP Serverが2026年7月28日の新しいMCP仕様に対応した。新仕様はステートレスな中核、初期化セッションの削減、公式適合性テストを特徴とし、リモートMCPサーバーを水平展開しやすくする。これは派手な生成機能ではないが、個人開発では重要である。認証、セッション保存、独自コネクター保守の負担を減らせれば、小規模なSaaSでも「顧客のエージェントから呼び出せる機能」を比較的短期間で商品化できるからだ。ただし、新仕様への完全対応状況はクライアントごとに確認が必要である。

収益化の観点では、汎用チャットの再包装より、既存業務の入口と成果物を固定した小さなエージェントが有望に見える。例えば、Linearの課題から定型的な修正PRを作る仕組み、Code Scanning警告の一次対応、スクリーンショットからUI差分を抽出する検査サービスなどである。販売対象を「AIを使いたい人」ではなく、「未処理課題や修正待ちを抱える小規模チーム」に絞れば、削減時間を価格根拠にできる。広告収益型アプリよりも少数顧客の月額課金に向き、実行回数やAIクレジットへ連動した従量制も設計しやすい。

注意点は、エージェント利用料が固定席課金だけでは把握できなくなったことだ。GitHub CopilotはAIクレジット方式を採用し、Codexも多くのプランでトークン量に対応するクレジット方式へ移行している。OpenAIはCodexの平均費用を開発者1人あたり月約100〜200ドルと説明しているが、モデル、並列実行、Fast modeで大きく変動する。したがって個人開発では、低単価の商品に無制限のエージェント実行を付けず、月間処理件数、最大トークン、再試行回数を制限すべきである。

次に取るべき一歩は、Linear連携そのものを購入することではなく、自分の開発工程から反復性の高い課題を10件抽出し、CodexまたはClaude Codeで完了率と原価を測ることだ。成功条件を「PR作成」だけでなく、テスト成功、レビュー修正回数、1件当たり推論費用まで含めて記録する。その結果から最も再現性の高い一工程をMCPツールまたは小規模SaaSに切り出し、月額課金できるかを検証するのが、短期リリースと収益化を両立する現実的な順序である。

## 個人開発で活用できそうなもの

- GitHub Copilot cloud agent for Linear: バグ、軽微な機能追加、テスト補強を課題単位で委任する。少人数でも「課題からPRまで」の待ち時間を短縮できる。
- GitHub MCP Server: Issue、PR、リポジトリ情報をエージェントへ接続する。セルフホスト可能で、日次トリアージやリリースノート生成の基盤に向く。
- GitHub Copilot Vision: 参考画面や不具合スクリーンショットからUI修正案を作る。ランディングページ量産や画像ベースの回帰確認に利用できる。
- Agentic Autofix: セキュリティ警告の調査と修正案作成を省力化する。保守込みの小規模SaaSで修正待ち時間を減らせる。
- Codex: 調査、実装、テスト、文書生成を並列委任する。利用上限を設けたうえで、複数のマイクロプロダクト運営を共通化できる。
