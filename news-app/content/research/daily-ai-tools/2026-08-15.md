## 記事本文

2026年8月15日の調査で最も重要だった変化は、新しい生成モデルそのものより、エージェントが「適切な道具を発見し、安全に実行する」ための基盤が急速に整ったことだ。GitHub Agent Finderとオープン仕様のAgentic Resource Discovery（ARD）は、あらかじめ大量のMCP定義をプロンプトへ詰め込む方式から、必要な機能だけを検索して接続する方式への移行を示している。これはコンテキスト消費を抑えるだけでなく、個人開発者が公開した小さなツールにも発見経路を与える。

MCP側では、7月28日版仕様がセッションレスな中核、キャッシュ可能な一覧、ヘッダールーティング、長時間処理用Tasksなどを導入した。従来のリモートMCPは、セッション維持や共有ストアが小規模サービスにも運用負担となりやすかった。新仕様なら一般的なHTTP基盤へ載せやすく、Cloudflare Workersなどの低コスト環境とも相性がよい。一方、旧セッションIDや実験版Tasksへ依存する実装には移行作業があるため、既存サーバーを無条件に更新すべきではない。

収益化の観点では、汎用チャットの再販よりも「特定業務をエージェントから呼び出せる小型サービス」に機会がある。たとえばApp Storeレビューの分類、競合価格の定点観測、将棋・麻雀棋譜の教材化、Shorts向け台本生成などをMCPツールとして提供し、無料のローカル版と監視・履歴・共有機能を備えた月額版に分けられる。ARDカタログへ登録できれば、独自の集客サイトだけに頼らず、Agent Finderなどから利用候補として発見される可能性も生まれる。ただしARDはv0.9 Draftであり、現段階では流入を保証する販売チャネルではない。

実装速度では、LinearのIssueからドラフトPRまで進めるCopilot cloud agentが短期リリースに直結する。ただしCopilotは月額料金に加えてAIクレジットを消費するため、反復回数の多い小規模案件では原価計測が欠かせない。Claude Tagはサポートや障害対応の自動化に有望だが、個人開発には価格と利用条件が重く、今は経過観察が妥当である。

次の一歩は、FastMCP 4を本番採用するのではなく、まず一つの読み取り専用ツールで試作することだ。入力検証、課金前確認、監査ログを備え、CodexとClaude Codeの双方から呼び出して成功率と一実行当たり原価を測る。その結果が安定してから、ARD用カタログと月額課金を追加する順序なら、仕様変更と運用費のリスクを抑えながら収益化仮説を検証できる。

## 個人開発で活用できそうなもの

- FastMCP 4: 競合調査、レビュー分類、棋譜解析などを読み取り専用MCPとして短期間で試作する。4.0系はプレリリースなので検証環境に限定する。
- GitHub Agent Finder: 自作MCPやスキルを独自ARDレジストリへ掲載し、エージェントから発見される導線を検証する。
- Copilot cloud agent for Linear: 不具合や小機能をIssue単位で実装させ、個人SaaSのリリース周期を短縮する。AIクレジット消費を案件別に記録する。
- GitHub Issues Agent Automation: 問い合わせの分類、重複候補、優先度付けを半自動化する。低信頼の変更を承認待ちにする運用が適する。
- hf-discover: ニッチ分野の推論APIやデモをARD対応させる際の検索・配布実装の参考にする。

- [MCP 2026-07-28仕様](https://blog.modelcontextprotocol.io/posts/2026-07-28/)が公開された。TypeScript、Python、Go、C#のTier 1 SDKが対応し、Rustはベータ対応。
