## 記事本文

2026年8月12日の調査では、単体のコード補完機能よりも、複数工程を引き受ける開発エージェントと、それらを外部サービスへ安全につなぐMCPの整備が重要な変化として見えた。特にGoogle AntigravityやCoder Agentsは、開発者が逐一コードを書く形から、要件を分割し、複数のエージェントへ実装やテストを委任する形への移行を示している。ただし、本日公開された新製品であることまでは確認できず、「本日の調査で新たに把握した候補」として扱う必要がある。

技術基盤では、2026-07-28版MCP仕様がステートレスなサーバー動作を重視し、GitHub MCP Serverや公式Go SDKが対応を進めている点が実用上大きい。セッション状態を特定サーバーに保持しない構成は、個人開発者でもサーバーレス環境へMCPを配置しやすく、障害復旧や水平分散も単純にできる可能性がある。一方、認証情報や書き込み権限をエージェントへ渡す危険は残るため、読み取り専用のツールセットから始める設計が妥当だ。

収益化の観点では、新しい汎用AIサービスを正面から作るより、既存業務の狭い範囲をエージェント化する方が短期リリースに向く。例えば、GitHub MCP ServerとCodexを組み合わせ、Issueの分類、変更候補の作成、テスト結果の要約までを月額制で提供する小規模な開発保守サービスが考えられる。また、学習アプリや麻雀・将棋アプリでは、問題生成そのものより、教材更新、誤答分析、短尺解説動画の台本生成といった運営工程を自動化する方が、品質を制御しながら利益率を上げやすい。

Coder Agentsのセルフホスト性は、顧客コードを外部の共有実行環境へ置きにくい案件で差別化要因になり得る。ただし、運用監視や計算資源の費用が発生するため、個人向けの低単価アプリより、保守契約や社内自動化など比較的単価の高い用途に適する。Google Antigravityは短期試作の速度向上が期待できるものの、料金と利用制限が未確認であり、原価計算を伴う本番採用は保留すべきである。

次に取るべき一歩は、GitHub MCP Serverを読み取り専用権限で接続し、既存リポジトリ一つを対象に「Issue確認、関連ファイル特定、修正案作成、テスト計画提示」までの所要時間を測ることだ。同時に、人手だけの場合と比較して、一件当たりの作業時間、モデル利用費、誤操作率を記録する。この小さな検証で採算が合えば、月額のリポジトリ保守支援や、特定カテゴリ向けアプリ量産工程へ展開できる。

## 個人開発で活用できそうなもの

- GitHub MCP Server: Issueの棚卸し、変更箇所の調査、Pull Request準備を半自動化する。まず読み取り専用で導入し、誤操作リスクを抑える。
- MCP Go SDK: 小型で配布しやすい業務特化MCPサーバーを作る。顧客ごとのデータ取得や定型処理を月額機能として提供できる。
- Google Antigravity: MVPの画面、API、テストを複数エージェントで並行試作する。料金が未確認のため、採算評価は実測後に行う。
- Coder Agents: 顧客コードを管理下の環境で処理する保守サービスに利用する。セルフホスト可だが、計算資源と運用費は別途必要。
- MCP公式Gitサーバー: ローカル履歴の調査や差分要約を自動化し、複数アプリの保守時間を削減する。
