## 記事本文

2026年8月29日の観測で最も重要なのは、新しい基盤モデルの性能競争よりも、エージェントを既存の仕事へ安全に組み込む「配布と操作面」の整備が進んだことである。GitHub CopilotのSlack・Microsoft Teams対応は、開発者がIDEを開いてから依頼する形を変え、相談が発生した会話から調査、実装、検証、Pull Request作成までを連続させる。作業の入口がコードではなく会話になった点は、少人数開発にも実務的な変化だ。

もう一つの転換点はAgent Plugins 1.0である。従来はClaude Code、Codex、Copilotなどの環境ごとにスキルやMCP設定を管理する負担があったが、共通パッケージ化が進めば、同じ業務手順を複数クライアントへ展開しやすくなる。個人開発者にとっては、完成アプリだけでなく「特定業務の知識、手順、外部サービス接続」をまとめたプラグイン自体を商品にできる可能性がある。ただし、対応範囲、署名、権限管理、マーケットプレイス間の互換性はまだ継続確認が必要だ。

収益化の観点では、汎用チャットをもう一つ作るより、狭い業種の反復作業をエージェント化する方が有望である。例えば問い合わせから再現テストと修正案を作る小規模SaaS、講義資料から復習サイトを生成する教育サービス、管理情報から週次レポートを作る運用支援などが考えられる。Education pluginsやAdmin pluginは、それぞれ教育・管理という明確な職務単位で機能を束ねており、「誰の何分を削減するか」を商品設計の中心に置く流れを示している。

一方、Slack版CopilotはBusiness・Enterprise中心で、Teams版もAIクレジットやサンドボックス費用が加わるため、個人開発の初期検証には重い。最初の一歩としては、無料で仕様を確認できるAgent Plugins 1.0を使い、ローカルまたはテスト環境だけを対象に、調査からMarkdownレポート生成までの小さなプラグインを試作するのがよい。実行時間、手修正率、1回当たり原価を記録し、節約時間が料金を上回る用途だけを月額商品へ進めるべきである。

## 個人開発で活用できそうなもの

- Agent Plugins 1.0: 市場調査、リリース確認、障害一次調査などをスキルとMCP接続込みで商品化する。顧客ごとの差分を設定ファイルへ寄せれば保守負担を抑えられる。
- Codex app server／Codex plugin: Claude Codeを主操作面にしながら、実装やレビューの一部をCodexへ委譲する開発パイプラインを構築できる。
- Education plugins: 学習資料からクイズ、復習計画、対話型教材を生成する日本語特化サービスの仮説検証に使える。ただし一般提供条件は未確認。
- Copilot in Slack: 有料顧客の不具合報告をIssue化し、再現調査と修正PRまで進めるB2B保守サービスに向く。個人利用には費用が重い。
- Admin plugin: 小規模組織向けに利用状況レポートや権限棚卸しを定期化できるが、操作対象と監査要件の事前確認が必要。

## Claude Code/Codex連携可能性

- Agent Plugins 1.0: スキルとMCPサーバー設定を一つにまとめ、対応するCodex・Copilot系クライアントへ共通配布する。Claude Codeの完全対応範囲は未確認。
- Codex plugin for Claude Code: Claude CodeのセッションからCodexへ作業を委譲する公式推奨経路として利用する。
- Codex app server: 非推奨のMCPサーバーコマンドに代わり、独自UIや自動化基盤からCodex機能へ接続する。
- GitHub Copilot SDK: Agent Plugins 1.0対応の独自エージェントアプリを作り、GitHub上のIssueやPull Requestと接続する。
- GitHub MCP連携: CodexまたはClaude CodeからIssue、Pull Request、リポジトリ情報を扱う。書き込み権限は最小化し、本番マージは人間承認とする。
