# Expo 移行方針

## 決定

- iOS 提出用の最終技術スタックは、ユーザー決定どおり Expo (React Native) とする。
- 現在の Next.js + Capacitor 実装は最終構成とはせず、Expo 版の機能一致を確認するための Web 基準実装として一時的に維持する。
- 新機能を Capacitor 固有 API に追加しない。解析ロジック、入力検証、端末内保存の仕様を Expo 版へ順次移す。
- 既存の `ios/` ディレクトリや Capacitor 依存は、Expo 版の同等フローとビルドが確認できるまで削除しない。移行途中の破壊的変更を避けるためである。

## 移行順序

1. `lib/mahjong/` の解析・入力検証ロジックとテストをフレームワーク非依存のまま共有する。
2. Expo 版に手牌入力、入力検証、解析結果、エラー・空・ロード状態を実装する。
3. Web の `localStorage` と同じ保存仕様を Expo の端末内ストレージへ置き換え、再起動時の自動復元を確認する。
4. Expo Web と iOS 実機で「入力 → 解析 → 結果表示 → 再起動時の復元」を通し確認する。
5. Expo 版の build / lint / typecheck / test と iOS 提出準備が完了した後に、旧 Capacitor 構成の撤去を別作業として行う。

## 完了判定

- 13枚の手牌で有効牌と受け入れ枚数を表示できる。
- 14枚の手牌で打牌候補、有効牌、受け入れ枚数を表示できる。
- 不正入力、空状態、解析中、予期しないエラー、オフライン状態を画面で扱える。
- 入力した手牌は端末内だけに保存され、アプリ再起動後に復元・再解析される。
- Expo Web と iOS 実機の主要フローが通り、クラッシュおよび未処理エラーがない。
- 課金、認証、外部送信は無料 MVP に含めない。ストア提出・公開はユーザーが行う。

## 現在の確認状況

- Web 基準実装では、14枚サンプルの入力、解析、結果表示、ブラウザー再読み込み後の入力・解析結果復元を確認済み。
- 下書きの検証・保存境界は DOM の `Storage` 型から分離済み。Expo 側は端末ストレージの同期アダプターをこの最小インターフェースへ接続するか、非同期版を追加して同じ検証規則を再利用する。
- Expo プロジェクトへの UI と端末内保存の移植、および iOS 実機確認は未完了。
