# 自動実行レビュー31: API安全性 棚卸し（Fableレビュー / claude）

## 1. API安全性の正本データ、派生ビュー、実行時に更新されるファイルを特定する
- 正本データ: API安全性の独立設定は無い。実態は Next.js のroute handler群(app/api配下21ディレクトリ)+ネットワーク層(next start -H 0.0.0.0 -p 3010、pm2管理)+ufw(3010/tcp ALLOW Anywhere)。認証ミドルウェア(middleware.ts)は存在しない。危険操作の防御はアプリ内のroutesToApprovalQueue(テキスト判定・レビュー10)のみ。
- 派生ビュー: 無し(横断的な非機能要件)。
- 実行時に更新されるファイル: 各APIがdata/real配下のJSONを書き換える。無認証でこれらが外部から操作可能。

## 2. API安全性の入口API/画面/自動起動経路と、出口の状態遷移を明記する
- 入口API: 全21グループ。状態変更系の例: POST /api/execution-runs(Run追加)、POST /api/operations/factory-run(Factory実起動・confirm:trueで実executor)、POST /api/goals(Goal CRUD)、POST /api/auto-queue/control(キュー操作)、承認・収益化・skills適用等。GETも含め全て無認証。
- 画面: 全画面が同じ無認証エンドポイントを利用。
- 自動起動経路: systemd/pm2はlocalhost経由だが、ネットワーク的には外部からも同一APIに到達可能。
- 出口の状態遷移: 認証・認可のゲートが無いため、リクエスト到達=実行。IP制限のみが唯一の境界だが、ufwが3010をAnywhere許可で開けている。

## 3. API安全性が失敗・未反映・重複した場合にどこで止まり、どの表示で気付けるかを確認する
- 失敗時: 個々のAPIはtry/catchで500を返すが、認証失敗という概念が無い(誰でも成功する)。
- 攻撃面: (1)無認証でfactory-runをauto/confirm起動され、AI executor(claude/codex CLI)を第三者トリガで動かされうる。(2)goals.json/epics.jsonを外部から書き換え・破壊できる(レビュー01/03の全消失経路を外部から誘発可能)。(3)入力サイズ制限が無くrawReport等に巨大ペイロードを送られJSONファイルを肥大化・ディスク圧迫できる。(4)CSRF対策が無くブラウザ経由の攻撃も成立しうる。
- 現実的リスク評価: 個人運用VPSで3010が知られていなければ実害確率は低いが、ポートスキャン+既知のNextパスで発見は容易。SSHが2222/22両開き等と合わせ、attack surfaceは小さくない。
- 重複: 該当なし。

## 4. API安全性についてFableレビューに渡す怪しい観点と、Todo消化漏れのような横断漏れ有無を記録する
- 【高・最優先】無認証+全開放ポート。progressはAI executorを起動でき、状態JSONを破壊できるため、無認証の実行系API公開は本レビューシリーズ全体で最も実害の大きい単一の問題。127.0.0.1バインドかWireGuard内限定にするだけで攻撃面の大半が消える。ネットワーク設定変更(ufw/バインド)は承認必須6点の該当外(本番課金/DB破壊等ではない)だが影響が大きいため、実行前にユーザー確認を推奨する。
- 【中】入力バリデーションの甘さ。サイズ制限・型検証が最小限で、巨大ペイロードや不正JSONでの状態破壊耐性が低い。
- 【中】CSRF/レート制限の不在。
- 【低】危険操作ゲートがテキスト判定のみ(レビュー10と同根)で、API層での操作制限は無い。
- 横断漏れ有無: セキュリティ観点では『防御が存在しない』ため漏れ以前の問題。この項目は他レビューの『データ破壊経路(01/03/12)』を外部から誘発可能にする増幅器であり、修正の費用対効果が最も高い。ネットワーク境界の是正を単独の承認事項として最終報告に上げる。
